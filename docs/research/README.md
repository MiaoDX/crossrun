## 已知需要修正的判断

### 01 生态调研

- **对 Isaac 生态的描述偏静态**。后续查证发现 Isaac Lab 已冻结 `main` 分支，物理层正从 PhysX 迁往 Newton（主后端为 MuJoCo-Warp）。这是本文档发布后才明确的重大变化。

### 02 对抗式评估

- **成本与算力章节的结论已不适用**。该文档假设团队算力受限，据此建议推迟 Isaac；实际有 4090 集群，该约束不成立。
- **"必须改"清单中关于商业化许可证的部分已不适用**——项目确定为开源，不做商业化。
- 但其中**关于 Isaac 生态 churn、统计功效、Goodhart 效应的分析仍然有效**，且已被后续证据加强。

### 03 人形框架穷尽调研

- **文档本身已纠正一处重要误判**：SIMPLE 并未内置 GEAR-SONIC，其 README 路线图中该项仍是未勾选的 TODO，仿真中实际使用的是 decoupled WBC。
- **其"以 fork SIMPLE 为底座"的核心建议后来被推翻**。原因是渲染吞吐：SIMPLE 单 GPU 光追约 4 fps，与目标统计规模（±2 个百分点置信区间需约 1030 次 rollout）相差 2–3 个数量级。SIMPLE 现定位为**任务设计参考**（MIT 协议，可合法借鉴），不作依赖。

## 一处被推翻的叙事

调研中期曾基于若干 GitHub issue 得出「VLA 复现危机」的判断。**这个框架已被否决**，原因是取证有偏——GitHub issue 本质是投诉渠道，没有人会开 issue 说"跑得很顺"。

反向查证后的准确图景是：**模型跑得动，榜出得来，可比性没问题。** 脆弱的只是"精确复现某个 headline 数字"，那是协议问题不是能力问题。相关证据见 `docs/plan.md` §3 的基线矩阵。

这个教训本身值得记录：**调研时主动搜索负面证据，会系统性地高估问题严重程度。**
